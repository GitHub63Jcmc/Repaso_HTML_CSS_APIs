Módulo 1. NUEVAS ETIQUETAS Y ATRIBUTOS DE HTML5

1.5 Elementos de formulario avanzados y nuevos tipos de input

Los formularios son la vía de entrada de datos del usuario, y la etiqueta <input> es su pieza más versátil[cite: 11]. HTML5 multiplicó los tipos disponibles y añadió validación nativa, de modo que muchas comprobaciones que antes exigían JavaScript ahora las realiza directamente el navegador[cite: 11].

Tipos de input en HTML5

Tipo de input Para qué sirve
email / url / tel Correo, dirección web y teléfono[cite: 11]. Validan el formato y en el móvil muestran el teclado adecuado[cite: 11].
number / range Valores numéricos: campo con flechas o control deslizante; admiten min, max y step[cite: 11].
date / time / datetime-local Selectores de fecha y hora nativos, sin necesidad de librerías externas[cite: 11].
month / week Mes o semana del año[cite: 11].
color Abre el selector de color nativo del sistema[cite: 11].
search Campo de búsqueda, con estilo y comportamiento propios en algunos navegadores[cite: 11].
file Selección de archivos; con el atributo multiple admite varios a la vez[cite: 11].
hidden / password / checkbox / radio Tipos clásicos que siguen siendo esenciales[cite: 11].

Validación Nativa y Elementos de Apoyo

  • Atributos de validación: required (campo obligatorio)[cite: 11], pattern (expresión regular que debe cumplir)[cite: 11], minlength, maxlength[cite: 11], min, max y step[cite: 11].
  • Estilos CSS por estado: Mediante pseudo-clases como :valid e :invalid se pueden resaltar los campos según su validez[cite: 11].
  • Nuevos elementos: <datalist> (lista de sugerencias para un input)[cite: 11], <output> (resultado de un cálculo)[cite: 11], <progress> (barra de progreso)[cite: 11] y <meter> (medida dentro de un rango)[cite: 11].
  • Atributos de ayuda: placeholder, autofocus y autocomplete[cite: 11].

💡 IDEA CLAVE: Validación en Cliente vs Servidor

La validación del navegador mejora la experiencia de usuario, pero nunca sustituye a la validación en el servidor[cite: 11]: cualquier usuario puede saltarse la validación del cliente[cite: 11]. Valida siempre en ambos lados[cite: 11].
