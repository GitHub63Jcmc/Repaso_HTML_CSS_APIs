3.11 Implementación de Web Workers: dedicados, compartidos y service workers

Bloque 3 · APIs de Interactividad y Rendimiento

JavaScript ejecuta todo en un único hilo principal, el mismo que pinta la interfaz. Si un cálculo tarda tres segundos, la página queda congelada tres segundos. Los web workers resuelven ese cuello de botella: son scripts que corren en paralelo, en un hilo aparte, y se comunican con la página por mensajes[cite: 18].

REGLA DE ORO DEL RENDIMIENTO: El hilo principal es para la interfaz. Todo cálculo pesado —procesar un archivo, filtrar miles de registros, comprimir una imagen— debería viajar a un worker[cite: 18].

Tipos principales de Web Workers

  • Worker dedicado: Se crea con new Worker('tareas.js'). La página le envía datos con postMessage() y los recibe con onmessage[cite: 18].
  • Worker compartido: Varias pestañas del mismo origen se conectan a un único proceso a través de un puerto (`SharedWorker`)[cite: 18].
  • Service worker: Un worker especial que actúa como proxy de red entre la web y el servidor, permitiendo funcionamiento sin conexión (PWA)[cite: 18].
